# FrameWorks recording access

TL;DR: a ready recording receives playback authority from its stored parent channel only after the provider confirms the exact JWT policy. The authority, catalog metadata and webhook receipt commit together.

The previous handler persisted recording metadata while the separate playback authority remained absent. This correctly denied playback but left saved replays unusable. The handler now protects the verified canonical recording hash and playback ID with the existing configured signing key and playback audience before calling the durable database boundary. It sets an internal policyConfirmed marker; event-supplied owners and flags are ignored.

The replacement webhook transaction requires that marker for recording-enabled channels. It derives the creator, MeToken gate and price from the stored parent channel, creates authority once, and mirrors the protected identity/access fields into the video row. Conflicting existing authority rolls back the receipt and metadata. Later events keep an existing recording's gate and archived state even when the parent settings change. Recording-disabled channels create neither a video nor playback authority. Upload and clip events retain readiness-only behavior and do not invent owners.

Apply the additive function migration to isolated QA before deploying the handler. An older handler without the confirmation marker fails closed for enabled recordings and can retry after deployment. The migration does not backfill existing recordings, change keys, add public grants or switch the production provider. Verify real recording delivery and playback after the handler is deployed; local tests do not establish those live results.

Validation: 26 focused handler/database tests, TypeScript and the integrated 1,404-test suite pass after incorporating the latest staging diagnostics and concurrent review fix. The tests cover owner/gate inheritance, policy failure before persistence, missing confirmation, conflicting authority, duplicate events, archival preservation and recording-disabled channels. The function migration is applied to isolated QA only. A real QA transaction verified owner/gate/catalog inheritance, then rolled back: receipt, authority and video fixture counts are all zero, recording remains disabled, and the anonymous role still cannot execute the function. Real provider recording/replay verification remains pending after the handler deployment.
